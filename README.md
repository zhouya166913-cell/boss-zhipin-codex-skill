# BOSS 直聘 Codex Skill

一个面向 Codex 的 BOSS 直聘招聘智能体 Skill，支持把自然语言招聘需求转成岗位画像、候选人搜索、简历匹配、个性化招呼、沟通监听、回复和面试邀约。项目使用隔离运行时、消息去重和显式写操作边界，避免误发或重复回复。

> 非 BOSS 直聘官方项目。BOSS 直聘没有面向公众的通用招聘开放 API。本项目依赖社区维护的 `jackwener/boss-cli` 锁定源码提交和用户本人的登录态，使用前请评估平台协议、账号风控和候选人隐私要求。

## 客户唯一使用方式

客户不需要安装 Skill、Python 或任何命令行工具，也不需要理解岗位 ID。只需把本项目地址和想做的事情一起发给 Codex：

```text
使用这个地址帮我操作 BOSS 直聘：
https://github.com/zhouya166913-cell/boss-zhipin-codex-skill

我要招聘一名上海的企业 AI 咨询顾问。你先查看我已有的岗位和候选人，
信息不够就直接问我，但不要让我安装东西或运行命令。
```

客户也可以只说一句很口语的话：

```text
用这个项目帮我从 BOSS 招一个销售，合适的先挑出来给我看：
https://github.com/zhouya166913-cell/boss-zhipin-codex-skill
```

如果客户只发送地址，Codex 会先问他要招聘人才还是找工作。客户不需要重新组织一份完整需求。

在另一台电脑首次使用时，不要直接让 Codex 登录。复制 [跨电脑与 WorkBuddy 使用指南](references/cross-device-onboarding.md) 中与账号状态对应的提示词。新客户自己的常用设备可以在明确确认后进行一次本人登录；近期出现过异常登录或 PC 端限制的同一账号，只能进入安全辅助模式，不能换设备同步登录态。

## 给读取本页的 Codex

如果你是因为用户提供了本仓库地址而读到这里，不要停留在项目介绍，也不要输出手动安装教程。立即读取 [SKILL.md](SKILL.md) 和其中按任务路由的参考文件，然后：

1. 自行获取项目并检查运行环境；
2. 自行创建隔离运行时并准备固定依赖；
3. 先确认账号、设备、地点和近期风控状态；只有用户明确批准后，才通过 `--confirm-auth` 请用户本人完成一次 BOSS 登录；
4. 先做不产生副作用的岗位和需求确认；
5. 信息不足时按照 [自然语言理解与主动反问](references/conversation-intake.md) 提问；
6. 发送消息、邀约、岗位修改和数据导出前，按照 `SKILL.md` 取得明确确认。

首次使用时 Codex 会自行：

1. 检查 Python 3.10+；
2. 在用户目录创建隔离虚拟环境；
3. 安装固定版本的 BOSS CLI 执行依赖；
4. 在用户明确批准认证且账号近期未受限时，引导用户本人扫码一次；
5. 先验证登录和只读能力；
6. 仅在用户明确确认后执行消息、邀约、岗位修改和数据导出。

环境检查会返回稳定状态：`runtime_missing` 表示需要自动安装，`runtime_incomplete` 表示需要重建固定运行时，`local_ready` 表示本机执行层可用并应进入账号风险确认。`local_ready` 不代表 BOSS 已登录。

环境缺失或准备失败时，Codex 应先按故障文档自行处理。只有操作系统权限、网络许可或本人登录确实需要用户动作时，才告诉用户点击或扫码，不把安装步骤转交给用户。

官方浏览器能够正常查看招聘页面，但 CLI 返回 `code=7` 或 `code=37` 时，说明浏览器与 CLI 会话分离，不代表项目已经打通。近期受限账号应停止 CLI，保留官方页面人工操作，由 Codex 或 WorkBuddy 只做离线分析和草稿生成。

## 支持自然语言二次开发

本项目允许用户的 Codex 在拉取仓库后直接进行本地二次开发，不要求每个兼容问题都等待本仓库更新。仓库根目录的 [AGENTS.md](AGENTS.md) 会告诉 Codex 如何分类故障、选择修改位置、保护数据和完成验证；详细开发方向见 [自然语言二次开发指南](references/secondary-development.md)。

用户仍然只需要说自然语言，例如：

```text
登录成功后一直掉线。请按项目里的二次开发指南诊断并修复，保留浏览器现场，
只做招聘端只读验证，不要重复让我扫码，也不要发送任何消息。
```

```text
这个接口现在返回新的错误码。请对照 BOSS 当前网页的只读请求，
在兼容层做最小修复并补测试；如果无法实机验证，要明确告诉我。
```

客户不需要指出文件名或运行命令。Codex 应自行读取项目说明、修改客户自己的本地分支并汇报结果；是否向本仓库提交改动由客户另行决定。

## 能力范围

招聘端：

- 查看已发布岗位；
- 搜索和查看推荐候选人；
- 查看候选人资料、简历和聊天记录；
- 根据简历证据进行匹配评分；
- 为不同候选人生成个性化招呼；
- 支持用户一次性指定岗位和人数上限后，对符合条件的候选人自动发送招呼，不逐人打断；
- 轮询沟通列表，只输出新增会话或消息变化；
- 在明确限定的招聘活动中处理基础自动回复；
- 经确认后回复、索要简历或联系方式、邀约面试；
- 经确认后上下线岗位、标记不合适或导出候选人。

示例对话：

```text
我要招聘一名上海的企业 AI 咨询顾问，3—5 年经验，做过企业 AI 转型或培训交付。
先查看我现有岗位，筛选 20 人，逐份简历评分，选出最合适的 5 人。
为每个人生成不同的招呼语，给我确认后再发送。
```

也可以直接建立一次性自动招呼活动：

```text
针对我当前的“销售市场总监”岗位，根据已有岗位说明筛选候选人。
本次最多联系 4 人，符合条件的直接发送个性化招呼，不需要逐人让我确认；
只在这一次任务内有效，任何一次发送失败或出现安全验证都立即停止。
```

这条自然语言本身就是本次活动的有限授权。Codex 仍会在本地完成预检、排除已沟通对象、逐个顺序发送并核验真实会话结果，但不会把候选人逐一交给用户点确认。

```text
监听这个岗位的沟通消息，每 60 秒检查一次。
候选人询问岗位职责或面试流程时可以按已确认信息回复；
涉及薪资、Offer、投诉或个人隐私时停止并通知我。
```

信息不完整时，Codex 不会机械地让客户填写表格。例如客户只说“帮我招一个销售”，Codex 会先只读查看已有岗位：唯一匹配时直接继续；有多个销售岗位时只让客户选择具体岗位；没有对应岗位时再询问岗位城市和核心职责。初筛数量等非关键项可以使用安全默认值，发送、面试和 Offer 等关键动作不能靠猜测。

## 当前边界

- 可以读取和管理已有岗位，但当前底层不能在 BOSS 创建新岗位；Codex 可以生成完整 JD，用户发布后再继续。
- 可以邀约面试。
- 可以起草 Offer 并在确认后作为聊天消息发送，但不支持 BOSS 平台的正式 Offer 功能。
- Skill 本身不是永久后台服务。持续监听需要保持任务运行，或另外配置 Codex 定时任务、`codex exec`、SDK/app-server或常驻服务。

求职端：

- 搜索、筛选和查看职位；
- 查看推荐、投递和面试记录；
- 经确认后向招聘者打招呼。

## 维护者自检

```text
python -m unittest discover -s tests -v
python scripts/bootstrap.py check
python scripts/inbox_monitor.py status
```

测试不会登录 BOSS，也不会访问候选人数据。真实连接需要用户本人登录，并且可能因平台接口变化而失效。

## 安全边界

- 不提交或展示 Cookie、Token 和浏览器凭证；
- 不绕过验证码、访问频率限制或平台风控；
- 不默认执行批量打招呼、自动回复或批量下载简历；自动回复必须限定岗位、时段、数量和消息类型；
- 普通远程写操作需要即时、明确的用户确认；限定岗位、当前任务和人数上限的一次性自动招呼活动可在开始时统一授权，不需要逐人确认；
- 批量操作必须先完成预检；没有一次性自动活动授权时仍需再次确认；
- 候选人信息和导出文件不得上传到公开仓库。
