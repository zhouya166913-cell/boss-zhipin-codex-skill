# 自然语言理解与主动反问

## 目标

用户只需要描述想招什么人、想筛谁或想做什么，不需要了解安装、命令、岗位 ID 和候选人 ID。Codex 负责把口语需求转成可执行招聘活动，并只在缺失信息会改变业务结果时追问。

## 决策流程

每次收到用户补充或纠正后，按以下状态推进：

`理解需求 → 只读发现 → 必要反问 → 形成计划 → 普通写操作预览确认 / 一次性自动活动授权 → 执行 → 监听或升级人工`

1. 从本轮消息和历史对话提取明确事实，区分“用户明确说明”“从已有岗位读取”“Codex 暂定”三种来源。
2. 如果只读查看岗位、简历或沟通列表能消除歧义，先查询再决定是否提问。
3. 将缺失信息分成安全默认、必须反问和禁止推断三类。
4. 暂定信息在第一次阶段性结果中简短说明；用户纠正后立即更新。
5. 远程写操作仍按 `SKILL.md` 的授权规则执行。普通发送需要预览确认；用户明确授权当前岗位、人数上限和筛选范围的自动招呼活动时，该授权可以覆盖活动内后续入选对象，不再逐人打断。

## 可以暂定，不阻塞只读工作的内容

没有其他上下文时使用以下默认值，并明确它们尚未获得最终确认：

- 初筛数量：20 人；
- 首轮建议联系人数：5 人；
- 沟通语气：专业、自然、不过度热情；
- 招呼语长度：60—120 个中文字符；
- 消息轮询间隔：60 秒；
- 排序方式：先核对硬性条件，再按简历证据评分；
- 信息未知：标记为“待确认”，不当作“不满足”。

这些默认值只用于查询、排序、生成草稿和提出建议。发送消息、邀约面试、修改岗位、导出数据和 Offer 不能因为默认值而自动获得授权。

## 必须反问的业务信息

出现以下情况时暂停相关步骤，但可以继续不受影响的只读工作：

- BOSS 中有多个可能的岗位，无法唯一确定本次招聘对应哪一个；
- 没有可读取的岗位说明，而且岗位名称、核心职责或至少一项硬性能力仍不明确；
- 用户要求“符合就联系”，但“符合”的标准存在互相冲突的说法；
- 普通发送没有自动活动授权，且发送对象、人数或完整消息内容还不能确定；
- 用户要求自动招呼，但唯一岗位或本次人数上限还不能确定；
- 要自动回复，但岗位、有效时段、最大回复数、允许处理的消息类型或停止条件未明确；
- 要约面试，但日期、时间、时区、地点/线上方式或时长缺失；
- 要发送 Offer 沟通，但岗位、薪资构成、试用期、工作地点、预计入职日、有效期或审批人确认缺失；
- 用户提到的人名、岗位或时间与 BOSS 当前数据不一致；
- 用户的最新要求会扩大已经确认过的发送范围。

薪资承诺、录用决定、淘汰决定、Offer 条款和歧视性筛选条件不得由 Codex 推断或默认。

## 怎么问

- 先用一句话复述已经理解的目标，再问缺少的关键点。
- 每轮最多问 3 个相互关联的问题，优先问能够解锁下一步的问题。
- 尽量给出从 BOSS 只读结果中得到的候选选项，并标出推荐项；不要把内部 ID 暴露给用户。
- 不使用“请提供参数”“请输入 ID”这类技术语言。
- 如果用户不知道答案，给出可逆的暂定方案，先做只读筛选，等发送或邀约前再确认。

推荐问法：

```text
我在你的 BOSS 账号里看到两个相近岗位：“企业 AI 咨询顾问”和“AI 培训讲师”。这次要筛哪一个？如果两者都要，我会分开评分，避免混在一起。
```

```text
我可以先按 20 人初筛、选 5 人生成招呼语。你有没有必须满足的一条条件，例如企业咨询交付经验？如果没有，我先按现有岗位说明筛，发送前再给你确认。
```

```text
要开启自动回复，我还需要你确定三件事：监听到什么时候、最多自动回复多少人、是否只自动回答岗位职责/地点/面试流程。建议先开 2 小时、上限 10 人，薪资和 Offer 一律转给你。
```

## 用户说错、改口或前后冲突

1. 最新的明确表述覆盖旧表述；明确表述覆盖 Codex 暂定值。
2. 只复述变化，例如：“已把工作城市从上海改为杭州，其他筛选条件不变。”
3. 如果尚未执行远程写操作，更新计划后从原步骤继续。
4. 如果消息或邀请已经发出，立即说明已经发生的动作和影响，不静默补发、撤回或改发；询问用户是否停止后续动作并生成纠正方案。
5. 薪资、日期、人数、候选人或岗位名称中的疑似口误，如果会影响写操作，必须确认，不能自行纠正。

## 只有一个地址时

用户只粘贴 GitHub 地址时，只问：

```text
我可以用这个项目接管 BOSS 直聘操作。你现在要招聘人才，还是以求职者身份找工作？
```

用户回答“招聘”后，先只读查看已有岗位；有且只有一个在招岗位时直接询问是否以它为目标，有多个时列出简短名称让用户选择，没有时询问想招聘的岗位名称和工作城市。

## 不应该问用户的内容

- 怎样安装 Python、Git、依赖包或 Skill；
- 要运行哪条命令、使用哪个目录或虚拟环境；
- Cookie、Token、`credential.json` 或浏览器凭证；
- `encryptJobId`、`friendId` 等内部标识；
- 已经能够从当前对话或 BOSS 只读数据确定的信息。

技术准备失败时，由 Codex 先按故障文档自行处理。只有确实需要系统权限、网络批准或本人扫码登录时，才用一句话说明用户需要完成的界面动作。

## 自动招呼时如何推进

用户已经指定唯一岗位和明确人数，并说“符合的直接打招呼”时，不要再要求逐人确认。先读取该岗位说明和推荐列表，用岗位相关证据筛选，在本地为入选者生成不同的招呼语，然后在人数上限内顺序发送。现有岗位说明可以作为筛选标准；沟通语气未指定时使用专业、自然、无薪资或录用承诺的默认风格。

这类授权只覆盖当前对话中的一次执行。岗位匹配到多个、人数不明确或岗位说明不足以判断时，只询问真正缺失的一个问题；不能把“自动”解释为不限人数、长期运行或跨岗位发送。
