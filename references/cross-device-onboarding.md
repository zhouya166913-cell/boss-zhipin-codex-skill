# 跨电脑与 WorkBuddy 使用指南

## 先区分两种情况

另一台电脑首次读取本项目时，Codex 必须先确认账号属于哪种情况：

1. **新客户自己的账号**：由客户本人在自己的常用设备和地点使用，近期没有异常登录、PC 端限制或安全验证。
2. **同一个近期受限账号换电脑**：包括刚恢复 PC 权限、官方网页正常但 CLI 返回 `code=7` 或 `code=37` 的账号。

第二种情况不得在另一台电脑发起 CLI 登录，也不得通过 WorkBuddy 电脑操作、移动端控制或自定义 MCP 同步会话。只能使用官方 BOSS 页面人工操作，Codex 或 WorkBuddy 做离线分析、评分和文案草拟。

## 给另一台电脑 Codex 的提示词

### 新客户账号首次使用

把下面整段和 GitHub 地址一起发给 Codex：

```text
请使用这个项目协助我的 BOSS 招聘工作：
https://github.com/zhouya166913-cell/boss-zhipin-codex-skill

这是本机首次使用。请先读取仓库根目录的 AGENTS.md、SKILL.md 和
references/cross-device-onboarding.md，自行完成项目获取、环境检查和隔离运行时准备，
不要让我安装软件或复制终端命令。

访问 BOSS 之前，先只问我一个问题：这个账号近期是否出现过异常登录、PC 端限制、
人脸验证或 code=7/code=37。未经我明确确认，不要执行 login，也不要读取、复制或展示
Cookie、Token 和浏览器凭证。

如果我确认账号由本人使用、当前设备和地点正常且近期未受限，只允许发起一次本人登录；
登录前使用项目的 --confirm-auth 安全门槛。登录后只执行一次招聘端只读检查。
如果返回 code=7、code=37 或任何安全限制，立即停止，不要再次扫码、刷新凭证或生成二维码。

发送消息、打招呼、邀约、岗位修改、下载或导出前，必须逐项向我展示并取得明确确认。
```

这段提示词允许 Codex 自动准备本地环境，但不授权它自动登录或执行任何 BOSS 写操作。

## 本地准备状态

Codex 应先运行离线环境检查，并严格按照返回的 `state` 处理：

| `state` | 含义 | 下一步 |
| --- | --- | --- |
| `python_unsupported` | 当前 Python 版本不足 | Codex 准备用户级或便携 Python；确需系统授权时再询问用户 |
| `runtime_missing` | 隔离运行时尚未安装 | Codex 自动执行固定版本安装 |
| `runtime_incomplete` | 运行时存在但招聘端命令不可用 | Codex 重新安装固定版本并再次离线检查 |
| `local_ready` | 本地执行层和招聘命令已加载 | 进入账号、设备、地点和近期风控确认，不得直接登录 |

环境检查和安装不得访问 BOSS。只有进入 `local_ready` 后，才允许讨论是否发起本人登录。

### 近期受限的同一账号

如果要在另一台电脑继续处理本次刚被限制过的账号，使用下面的提示词：

```text
请读取这个项目并进入安全辅助模式：
https://github.com/zhouya166913-cell/boss-zhipin-codex-skill

这个 BOSS 账号近期出现过异常登录和 PC 端限制，官方浏览器可能已恢复，
但 CLI 曾返回 code=7。不要执行 login、status、recruiter 命令或任何 BOSS 网络请求；
不要控制浏览器或手机，不要同步 Cookie、刷新凭证或生成二维码。

你只负责根据我主动提供的脱敏岗位信息和候选人资料，完成岗位画像、匹配评分、
招呼语、回复草稿和面试准备。所有内容由我在 BOSS 官方页面人工确认和操作。
```

## 给 WorkBuddy 的提示词

WorkBuddy 可以读取项目规则、管理任务和生成招聘产物，但它的电脑操作、自定义 MCP 或移动端控制不等于 BOSS 官方授权。建议使用：

```text
请读取并遵守这个项目的招聘工作流和安全边界：
https://github.com/zhouya166913-cell/boss-zhipin-codex-skill

使用安全辅助模式：不要登录或自动操作 BOSS 网页、APP，不要调用私有 BOSS 接口，
不要通过 MCP 同步 Cookie。只处理我主动提供的脱敏岗位和候选人信息，完成匹配分析、
沟通草稿、面试问题和待办提醒。任何 BOSS 页面操作都由我本人完成。
```

如果 WorkBuddy 当前版本不能直接读取 GitHub 仓库，不要让它自行创建一个声称兼容的 BOSS 连接器。应改用 Codex 读取仓库，或通过 WorkBuddy 官方支持的本地 Skill 导入方式加载经过核验的项目包。

## 登录与停止条件

- 本地环境安装不等于登录授权；Codex 可以自动准备运行时，但不能自动取得 `--confirm-auth`。
- 用户明确批准后，一次任务最多发起一次本人登录。
- 登录后最多执行一次 `recruiter jobs --json` 只读检查。
- `code=7`、`code=37`、PC 端限制、人脸验证或设备校验任一出现，立即停止。
- 官方网页正常但 CLI 失败，不得宣称 Skill 已打通；应报告“浏览器可用、CLI 未认证”。
- 新电脑不得复用、传输或提交旧电脑的 Cookie、Token、`credential.json` 或浏览器配置目录。

## 什么情况下可以继续

只有以下两类情况可以继续自动执行：

1. 客户取得 BOSS 正式授权的企业接口或 ATS 集成，并明确批准相应读写权限；
2. 项目在客户自己的常用设备上完成一次本人登录，招聘端只读检查成功，且没有出现任何安全限制。

即使只读检查成功，消息、邀约、岗位状态变化、下载和导出仍需遵守 `SKILL.md` 的即时确认与批量门槛。
