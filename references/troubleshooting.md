# 故障排查

## Python 不可用

要求 Python 3.10 或更高版本。由 Codex 依次检查：

```text
py -3 --version
python3 --version
python --version
```

不要让用户运行这些命令。如果没有可用版本，Codex 优先使用当前环境已有的包管理能力准备用户级或便携 Python，不修改项目依赖，也不静默进行系统级安装。只有操作系统要求本人批准安装或当前环境禁止下载时，才简短说明唯一需要用户完成的授权动作；不要给用户一套手动安装教程。

## 运行时未安装

先执行只读检查：

```text
<python> scripts/bootstrap.py check
```

若 `installed` 为 `false`，Codex 从 GitHub 安装锁定的 `jackwener/boss-cli` 源码提交到输出中的 `runtime_root`，然后执行：

```text
<python> scripts/bootstrap.py install
```

不要把运行时建在仓库内，也不要修改项目依赖文件。

## 登录失败

1. 确认用户可以在普通浏览器中正常打开并登录 `https://www.zhipin.com/`。
2. 确认账号由本人使用、当前设备和地点正常，并询问账号近期是否出现异常登录或 PC 端限制。近期受限的账号停止 CLI 登录，只使用官方页面。
3. 用户明确批准一次认证后，执行 `<python> scripts/boss_safe.py --confirm-auth -- login --qrcode`，由用户本人扫码。
4. 如果二维码登录缺少浏览器生成的会话信息，不要自动开始第二次登录；先按本页会话分离状态判断是否应停止。
5. 不让用户把 Cookie 或 Token 粘贴到聊天中，不读取浏览器凭证数据库内容。

## Windows 浏览器 Cookie 无法读取

新版 Chrome/Edge 可能阻止外部程序解密 Cookie。优先使用二维码登录。只有用户明确同意时，才按照上游工具提示使用独立浏览器配置和本机回环 CDP；不得连接非回环 CDP 地址。

## code 37、登录过期或接口变化

先执行：

```text
<python> scripts/boss_safe.py -- status --json
```

招聘场景不能只依赖通用状态探针。状态检查后，再用 `recruiter jobs --json` 做一次招聘端只读验证：如果招聘端命令成功，不要因为求职端探针失败而要求用户重新登录。

若招聘端也返回 `code=7`、`code=37` 或登录失效，同一任务最多从仍打开的专用浏览器刷新凭证一次，并用同一只读命令复验一次。复验仍失败时，停止重新登录循环，不再生成二维码；将状态标记为“会话不稳定”，保留浏览器现场并读取 [自然语言二次开发指南](secondary-development.md) 排查角色验证、浏览器配置和会话刷新逻辑。

如果官方浏览器中的招聘页面和候选人推荐正常，但 CLI 的招聘端只读命令返回 `code=7`，应标记为“浏览器已登录、CLI 未认证”，而不是“PC 端仍被限制”。账号近期出现过 PC 端限制时，立即停止 CLI，不导入 Cookie、不刷新凭证、不再次扫码；后续只允许官方页面人工操作和离线分析。另一台电脑的处理方式见 [跨电脑与 WorkBuddy 使用指南](cross-device-onboarding.md)。

若登录正常但业务接口持续失败，停止写操作并报告具体命令、退出码和已脱敏的错误信息。不要通过伪造指纹、提高请求频率、验证码求解或改写安全参数规避限制。

## 写操作被包装器阻止

- `--confirm-auth` 缺失：先确认账号、设备、地点和近期风控状态，只能在用户明确批准后发起一次本人登录。
- `--confirm-write` 缺失：先向用户展示准确对象、动作和文本并取得确认。
- `--allow-batch` 缺失：先执行 `--dry-run`，展示批量范围并取得第二次确认。
- 不要修改包装器来绕过这些保护。

## 招聘端候选人列表返回 1093

如果 `recruiter inbox` 在登录有效、岗位列表可读时返回平台业务码 `1093`，先确认命令是通过 `scripts/boss_safe.py` 执行，而不是直接调用隔离运行时中的 `boss` 可执行文件。

当前 BOSS 网页的 `filterByLabel` 请求体使用 `labelId` 和 `encJobId`，不再发送旧版 `page` 字段。本项目的 `scripts/boss_cli_compat.py` 会在运行时修正锁定版上游 CLI 的这一处参数差异。不要通过反复登录、提高频率或绕过验证来处理 `1093`。

更新项目后仍返回 `1093` 时，停止候选人列表、消息监听及后续写操作，记录命令名、业务错误码和发生时间；不要记录 Cookie、Token、候选人姓名或消息正文。重新核对 BOSS 官方网页的同一只读请求后，再更新兼容层和回归测试。
